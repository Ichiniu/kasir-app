ARSITEKTUR DATABASE
Database internal n8n menyimpan workflow/credential/execution, BUKAN sumber laporan kasir.
Workflow nantinya membaca database aplikasi kasir melalui credential PostgreSQL terpisah.
Gunakan akun read-only khusus laporan, bukan akun aplikasi/Prisma, postgres superuser,
atau credential database milik bot lain. Tidak ada migrasi/penyalinan data saat ini.

TOOL YANG DISIAPKAN
1. laporan_penjualan — omzet COMPLETED, transaksi, item, diskon/pajak per outlet.
2. penjualan_harian_pembayaran — rincian harian WIB dan metode pembayaran.
3. sesi_kasir — buka/tutup dan penjualan yang masuk periode laporan.
4. produk_terlaris — jumlah dan subtotal item; bukan omzet net setelah diskon/pajak.
5. stok_produk — persediaan, minimum stok, harga/modal terkini.
6. bahan_baku — persediaan fisik disetujui Admin, satuan masing-masing.
7. stock_opname — pagi/sore, status, stok hitungan/fisik, catatan/kolom tambahan.
8. permintaan_bahan — tanggal kebutuhan, status, jumlah, catatan.
9. mutasi_stok_produk — stok masuk/keluar manual produk.
10. daftar_transaksi — invoice dan semua status; tanpa PII pelanggan.
11. katalog_outlet_kategori_sku — katalog scoped outlet.

Tidak membaca accounts, sessions, verifications, settings, audit_logs, password/token.
User hanya dibaca namanya untuk kasir sesi dengan join outlet yang sama.
Tidak ada model inventaris resep/BOM atau snapshot modal historis di schema yang diperiksa;
jangan mengklaim konsumsi bahan otomatis atau laba historis akurat.

KONFIGURASI YANG DILENGKAPI NANTI
1. Owner mapping di node Konfigurasi Casir:
   { active: true, phone: nomor internasional tanpa +,
     deviceId: JID device pada webhook GoWA,
     gowaDeviceId: ID/session pengirim yang dikenali node GoWA,
     ownerId: identitas pemilik yang telah diverifikasi,
     outletIds: [ID outlet sah milik pemilik] }
   Verifikasi mapping melalui jalur Admin/owner tepercaya, bukan klaim lewat chat.
   Satu nomor/device hanya boleh satu mapping; daftar kosong menolak semua.
   Mapping sementara pada konfigurasi, tidak berarti kolom WhatsApp sudah ada di users.
   Kelak bisa diganti lookup otorisasi; jangan menghapus pembatasan query.
2. Koneksi read-only ke database kasir, TLS sesuai jaringan; allowlist tabel,
   statement_timeout (misalnya 10 detik) dan prinsip hak minimum pada role database.
   Untuk isolasi tingkat database pertimbangkan reporting views/RLS sesuai role
   sebelum produksi. Draft saat ini menegakkan outlet scope pada query, belum RLS.
3. Pilih credential ini pada 11 node postgresTool dan bandingkan skema server
   dengan prisma/schema.prisma lokal. Jangan mengubah database internal n8n.
4. Set webhook GoWA dengan path /webhook/casir-owner-report setelah persiapan live.
   Draft memakai payload modern { event, device_id, payload: { id, from,
   chat_id, body, is_from_me, timestamp } }. Grup, self, receipt, media nonteks,
   pesan >1500 karakter, event kedaluwarsa >5 menit, dan @lid ditolak.
   Format legacy perlu adapter setelah melihat fixture nyata; jangan tebak identitas LID.
5. HMAC SHA256 X-Hub-Signature-256 atas RAW bytes, secret acak >=32 karakter.
   Gunakan secret GoWA tersendiri, bukan API key n8n dan bukan default 'secret'.
   Code node mengacu CASIR_GOWA_WEBHOOK_SECRET serta require('crypto').
   Periksa kebijakan task runner/env terlebih dulu: jika akses env/crypto tidak
   diizinkan, verifikasi gagal tertutup. Pakai secret store/gateway tepercaya bila
   tersedia; jangan melonggarkan kebijakan env global tanpa penilaian.
6. Anti-replay timestamp ada, tetapi DEDUPLIKASI ATOMIK dan RATE LIMIT belum
   dipasang. Wajib sediakan pada gateway/ingress sebelum ingressControlsReady=true.
   Scope dedup per device+message ID; klaim atomik dan TTL, termasuk retry/concurrency.
   Jangan menganggap staticData workflow sebagai lock andal untuk multi-worker.
7. Credential GoWA dan model yang direferensikan berasal dari instance yang sama;
   model bernama opencode mengikuti konfigurasi bot yang sudah ada.
   Uji kompatibilitas tool calling dan device yang benar sebelum aiReady=true.
   Penerima balasan diambil dari owner terverifikasi, tidak dari model AI.
8. Aktifkan databaseReady/aiReady hanya sesudah tes, sendReplies setelah uji
   dengan nomor owner/test yang disetujui. liveEnabled dan ingressControlsReady
   tetap false sampai checklist lolos. Lalu publish secara sengaja.

KEAMANAN DAN OPERASIONAL
- Workflow tidak mengubah POS, stok, approval opname, atau transaksi.
- Query tetap/parameterized; AI tidak boleh memasok SQL atau scope sendiri.
- Tanggal inklusif WIB, maksimal 366 hari. Timestamp Prisma diasumsikan UTC
  dalam PostgreSQL timestamp without time zone sesuai migrasi lokal; verifikasi server.
- List dibatasi dan envelope menyertakan truncated/row_count. Jangan gunakan
  daftar terpotong sebagai total; gunakan laporan_penjualan untuk agregat omzet.
- Tidak ada chat memory bersama; pertanyaan lanjutan wajib menyebut konteks lagi.
- Kegagalan agent ditangani dengan pesan generik; balasan tanpa tool evidence
  diarahkan meminta jenis laporan/outlet/tanggal, bukan angka rekaan.
- Penyimpanan execution sukses/error/manual dimatikan untuk draft agar laporan
  tidak tersimpan. Sebelum produksi rancang audit metadata minimal tanpa isi pesan,
  retry/recovery, rate limit, dan pemantauan kegagalan pengiriman.
- ACK webhook diberikan setelah verifikasi HMAC, sebelum proses AI. Jaminan
  antrean/retry durable belum disediakan; uji penanganan gagal setelah ACK.
- Tes live nanti harus mencakup: dua owner dua outlet, penolakan lintas outlet,
  batas tanggal WIB, transaksi batal/refund, join item tanpa menggandakan omzet,
  sesi terbuka lintas hari, opname dan satuan, query timeout, signature salah,
  event duplikat/bersamaan, model gagal, dan GoWA gagal tanpa pesan ganda.
