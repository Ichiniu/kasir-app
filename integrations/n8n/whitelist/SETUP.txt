PENANGANAN GAGAL
Perintah admin lewat jalur deterministik, tidak lewat model AI atau SQL buatan AI.
Perintah admin tidak memerlukan aiReady=true, tetapi databaseReady dan preflight
read-only tetap diperlukan agar nama/ID outlet dapat diperiksa saat konfirmasi.
Semua permintaan tetap melewati batas beban, dedup, penyimpanan balasan dan claim
kirim sekali. Rate limit memakai ownerId bersama untuk owner dan semua anggota.
Artinya batas 3 pesan/menit dan 100/24jam berlaku gabungan untuk satu owner/device.
Jika hasil kirim ambigu, jangan otomatis mengulang konfirmasi. Cek lihat whitelist
atau audit setelah layanan pulih. Perubahan tercatat bersama ID pesan asal.
Pending dan hasil perintah dibersihkan saat ada perintah admin berikutnya: pending
>1 hari setelah kedaluwarsa, hasil >7 hari, audit >90 hari. Jika tidak ada perintah
baru, record tetap tersimpan sampai maintenance manual; kedaluwarsa tetap ditegakkan.
